## Estudios de caso (Nivel 3)

### Caso 1: `ArrayList` vs `LinkedList` en lista de tareas
**Escenario:** una app de tareas inserta al final, recorre mucho y casi nunca inserta en medio.

- `ArrayList` suele ser mejor por localidad de memoria y acceso aleatorio O(1).
- `LinkedList` solo gana si hay muchas inserciones/eliminaciones internas con iteradores ya posicionados.
- **Decisión recomendada:** empezar con `ArrayList` y medir antes de optimizar.

### Caso 2: `HashMap` vs `TreeMap` en ranking de palabras
**Escenario:** contar frecuencia de palabras de un `.txt` y exportar top resultados.

- `HashMap`: inserción/consulta promedio O(1), ideal para conteo masivo.
- `TreeMap`: mantiene orden natural O(log n), útil si necesitas salida ordenada por clave.
- **Estrategia práctica:** contar con `HashMap` y ordenar al final solo para presentación.

## Mini-proyecto guiado

### Analizador de Logs Java
Construye una herramienta CLI que lea un archivo de logs y genere un resumen:

1. Leer archivo con `Files.lines(Path)` y `try-with-resources`.
2. Parsear severidad (`INFO`, `WARN`, `ERROR`) y timestamp.
3. Contar ocurrencias por severidad con `Map<String, Integer>`.
4. Exportar resumen a CSV (`severidad,total`).
5. Manejar errores con excepción personalizada (`LogFormatException`).

**Criterios de buena solución:** código desacoplado (parser/servicio/exportador), manejo correcto de excepciones y tests de parseo.

## Errores comunes (y cómo evitarlos)

- Capturar `Exception` genérica para todo → captura lo específico primero.
- Usar `LinkedList` por “intuición” sin medir → elige estructura por patrón de acceso.
- Ignorar genéricos (`List` en crudo) → usa tipos parametrizados para evitar errores en runtime.
- Leer archivos sin cerrar recursos → usa `try-with-resources` siempre.
