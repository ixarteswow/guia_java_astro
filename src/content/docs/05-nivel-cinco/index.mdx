## Estudios de caso (Nivel 5)

### Caso 1: Maven + JUnit en proyecto real pequeño
**Escenario:** API de tareas con capas (`domain`, `service`, `infra`).

- Maven centraliza dependencias, plugins y ciclo de build.
- JUnit valida reglas de negocio sin levantar toda la app.
- **Resultado esperado:** build reproducible y suite de tests rápida.

### Caso 2: Estrategia de ramas para equipo pequeño
**Escenario:** 2-3 desarrolladores colaboran en features semanales.

- `main` protegida + ramas `feature/*` + PR obligatoria.
- Commits atómicos con mensajes claros (`feat:`, `fix:`, `test:`).
- **Beneficio:** historial limpio y menor riesgo de romper producción.

## Mini-proyecto guiado

### API de Tareas “portfolio-ready”
Implementa una app (consola o web simple) con enfoque profesional:

1. Inicializa proyecto con Maven/Gradle.
2. Modela entidad `Task` y casos de uso CRUD.
3. Persistencia simple en JSON.
4. Pruebas unitarias para reglas clave (estado, validaciones, filtros).
5. README con instalación, ejecución, tests y decisiones técnicas.
6. Flujo Git: al menos 1 feature branch + 1 PR documentada.

**Criterios de buena solución:** cobertura de casos críticos, estructura clara, README útil y trazabilidad en Git.

## Errores comunes (y cómo evitarlos)

- Mezclar lógica de negocio y acceso a datos en una sola clase.
- Escribir tests frágiles acoplados a implementación interna.
- Commits grandes “todo en uno” difíciles de revisar.
- README mínimo sin instrucciones reproducibles.
